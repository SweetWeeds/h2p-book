연구 계획: 무엇을 검증할 것인가

정보를 더 얻고, 필요한 상태를 남기고, 제때 사용하는 방법을 실제 연구 질문으로 바꿔 보자. 목표는 강한 기준 예측기에서도 남는 오예측을 줄이면서, 추가 비용을 감당할 수 있는 한 가지 주된 기여를 찾는 것이다.

이 장에서 배우는 것

  • 현재 우선 검증할 방향과 추가 검토 후보를 구분한다.
  • 컴파일러가 알려 주는 분기 관계와 실행 중 필요한 정보를 구분한다.
  • 재현, 정보 시점, 공정한 비교, 비용을 기준으로 연구의 다음 단계를 판단한다.

현재 위치: 가설을 검증하기 전

계획의 상태 · 2026-10-07

이 장은 현재 통합 계획과 후속 검토를 설명형 이름으로 정리한 공개 요약이다. 신규 성능 실험 결과는 아직 없다. 연구 범위에 대한 합의가 성능이나 신규성의 입증을 뜻하지 않는다. 세부 구현과 일부 평가 기준은 실행 전에 확정해야 한다.

10장의 정보·상태·시간 관점에서 세 가지 질문을 다룬다. 여러 방향을 처음부터 합치기보다 각 방향의 효과와 비용을 따로 확인한다.

질문검증할 방향현재 범위
무엇을 기억하고 어떤 출력을 쓸까?예측기 구성 요소의 신호를 함께 쓰는 제어우선 구현할 두 행동 파일럿
실제 값이 나오면 아직 고칠 시간이 있을까?값 도착 이후 재예측 기회 측정실행 기록을 이용한 분석; 실제 경로 수정 제어는 보류
긴 이력 중 어떤 분기를 참고할까?관계에 따른 이력 선택학습 구간에서 만든 관계 정보를 고정해 평가

첫 방향: 기억할 패턴과 사용할 출력 선택

TAGE는 여러 길이의 이력을 사용한다. 통계적 보정기(SC)는 추가 신호로 예측을 보정한다. 두 구성 요소가 관찰한 신뢰도와 유용성을 함께 사용하면, 각각 독립적으로 제어할 때보다 나은 결정을 내릴 수 있는지 묻는다.

  • 새 패턴의 할당 허용 여부: 원래 예측기가 새 항목을 만들려고 할 때 허용하거나 거부한다. 정답을 맞힌 경우에도 할당 요청이 발생할 수 있으므로 실제 코드의 모든 요청을 기준으로 삼는다.
  • 레지스터 값 기반 보정의 사용 여부: 값 정보를 포함한 출력과 제외한 출력 가운데 하나를 선택한다. 이 파일럿에서는 계산과 학습을 유지하므로, 출력 선택만으로 에너지 절감을 주장하지 않는다.

원래 예측기, 독립 제어, 각 행동만 적용한 구성, 두 행동을 결합한 구성을 비교한다. 같은 추가 저장공간을 기존 예측기 확대에 썼을 때의 결과도 확인한다. 신뢰도만 사용하는 단순 정책보다 복잡한 제어가 실제로 나은지 검증해야 한다.

할당을 거부하면 이후의 학습과 경쟁도 바뀐다. 별도 실행에서 좋았던 분기만 골라 합친 결과를 하나의 실행 가능한 정책의 성능으로 취급하지 않는다.

둘째 방향: 값이 도착한 뒤 남는 시간

예측할 때는 없던 실제 레지스터 값이 실행 도중 나올 수 있다. 그 값으로 방향을 다시 판단했을 때, 분기의 정답이 확정되기 전에 수정할 여유가 남는지를 측정한다. 5장의 값 기반 접근과 연결되는 질문이다.

  1. 최초 예측 때의 이력과 예측기 상태를 보존한다.
  2. 분기 입력 또는 그 입력을 만드는 연산의 입력이 언제 도착했는지 추적한다.
  3. 새 값으로 재평가했을 때 유용한 변경과 해로운 변경을 함께 센다.
  4. 입력 수집·재평가·전달 지연을 고려해 정답 확정 전에 도착하는지 확인한다.
시간 여유와 성능 이득은 다르다

실제 값 도착부터 정답 확정까지 남은 시간은 기회의 크기다. 그 시간이 모두 실행 시간 절감으로 이어지는 것은 아니다. 최종 성능에는 경로 수정과 복구 비용을 포함한 실행 모델이 필요하다.

현재는 레지스터 값을 이용한 분석까지 수행하는 계획이다. 실행 중 수정 여부를 학습하는 제어기와 부분 복구 구조는 입력·기회·비용을 확인한 뒤 별도로 설계한다.

셋째 방향: 관련 있는 분기 이력만 선택

긴 이력에는 관련 분기와 무관한 분기가 섞여 있다. 앞선 조건이 뒤에서 검사할 값을 결정하거나, 여러 분기가 같은 값에서 파생된 조건을 검사할 때 관계를 이용할 수 있다. 핵심 질문은 같은 개수의 이력을 사용해도 관계를 기준으로 고른 이력이 더 유용한가이다.

먼저 학습 구간에서 만든 관계 정보를 평가 전에 고정한다. 최근 이력, 무작위 이력, 통계적으로 고른 이력, 관계로 고른 이력을 같은 후보 범위·선택 개수·보조 예측기 조건에서 비교한다. 보조 예측기 자체의 학습과 초기화 조건도 맞춘다.

  • 정보 시점: 최초 예측과 늦은 재예측을 분리한다. 실행 뒤에 알아낸 관계나 값을 과거 예측 시점으로 소급하지 않는다.
  • 메모리: 메모리 관계를 제외한 경우, 주소 생성만 추적한 경우, 실제 값을 전달한 저장까지 추적한 경우를 구분한다. 값이 같다는 이유만으로 같은 저장에서 왔다고 판단하지 않는다.
  • 실행 연결: 같은 분기 명령어의 여러 반복 중 어떤 결과를 선택했는지 검사한다. 가장 최근 결과와 올바른 결과가 항상 같지는 않다.
  • 용량: 기본 예측기와 저장 구조를 확대한 예측기에서 모두 측정한다. 결과 차이를 하나의 원인으로 단정하지 않는다.

기본 구현안은 이력의 위치를 선택하는 방식이다. 분기 명령어의 주소로 과거 결과를 찾는 방식은 별도 변형이며, 검색과 반복 연결 비용을 추가로 계산해야 한다.

추가 검토: 컴파일러가 분기 관계를 알려 준다면

검토 가설: 컴파일러가 관련 분기 후보를 제공하면 실행 중 관계를 발견하는 비용을 줄이고, 다른 입력에서도 유용한 이력을 선택할 수 있을까? 이 가설은 후속 제안이며 아직 구현·성능·신규성이 검증되지 않았다.

관계쉬운 예확인할 한계
앞선 조건이 값의 생성을 결정앞선 조건에 따라 다른 값을 대입하고 뒤에서 검사어느 경로의 값이 실제 사용됐는가
공통 값을 검사변하지 않은 값이 10보다 큰지, 이어서 20보다 큰지 검사부분적 정보일 수 있으며 쉬운 관계는 최적화로 제거될 수 있음
반복 사이에 상태 전달이전 반복에서 선택한 상태를 다음 반복에서 검사올바른 반복의 결과를 찾을 수 있는가
메모리를 통해 값 전달조건부 저장의 값을 나중에 읽어 검사정적 분석으로 실제 저장·읽기 연결을 확정하기 어려움

실행 순서를 나타내는 제어 흐름만으로는 충분하지 않다. 값의 정의·사용, 조건에 따른 값 선택, 반복과 메모리 의존성을 함께 분석해야 한다. LLVM의 MemorySSA는 메모리 분석의 기반이지만 실제 실행의 모든 연결을 확정해 주지는 않는다.

작게 시작할 구현안

  1. 컴파일: 최적화 후에도 남아 있는 어려운 분기의 관련 후보를 찾는다. 프로파일을 쓰는 경우와 쓰지 않는 경우를 분리한다.
  2. 정보 전달: 목표 분기마다 소수의 참조 분기와 관계 종류를 저장한다. 최종 기계어 위치와 연결하고 예측 전에 정보를 준비한다.
  3. 실행 기록: 관련 분기의 결과, 유효 여부와 필요한 반복 정보를 기록한다.
  4. 예측 보정: 선택된 이력을 작은 보조 예측기에 입력한다. 정보가 없거나 신뢰도가 낮으면 기존 예측을 사용한다.

그래프는 컴파일 단계의 분석 표현으로 사용하고 예측 시점에는 제한된 표 조회로 처리하는 설계가 출발점이다. 실행 파일에 정보를 넣는 것만으로 기존 CPU가 활용하지는 않으며, 이를 읽는 하드웨어 지원이 필요하다.

관계를 알아도 해결되지 않는 두 문제

어느 실행인가: 같은 명령어라도 현재 반복, 이전 반복, 마지막으로 특정 조건을 만족한 반복의 결과는 다르다. 처음에는 같은 반복 또는 일정한 반복 간격을 식별할 수 있는 관계부터 평가한다.

언제 알 수 있는가: 앞선 분기의 실제 결과도 아직 미확정일 수 있다. 예측값을 사용하면 잘못된 경로의 상태를 복구해야 하고, 확정된 결과만 사용하면 적용 범위가 줄어든다. 목표 분기 바로 앞의 힌트를 실행한 뒤 전달하는 방법은 최초 예측에 늦을 수 있다.

비교할 방법답하려는 질문
기존 TAGE-SC-L강한 기준 예측기 대비 개선 여지가 있는가
프로파일만으로 선택실행 통계만으로 충분한가
컴파일러 관계만으로 선택학습 프로파일 없이도 효과가 있는가
컴파일러 후보를 프로파일로 선별구조와 통계를 결합할 가치가 있는가
실제 관계와 실행 연결을 완벽히 아는 경우정적 분석과 실행 연결 때문에 얼마나 손실되는가; 구현 가능한 성능으로 해석하지 않음

같은 최적화 바이너리와 입력 분할을 사용하고, 정보 저장·검색·전달·복구 비용을 포함한다. 이력 위치를 고르는 기존 분석과 주소로 관련 분기를 찾는 변형의 차이도 따로 측정한다.

선행연구와 구분할 기여

관계를 이용하거나 소프트웨어가 예측을 돕는 발상 자체는 선행연구가 있다. 새로운 기여는 더 낮은 비용, 더 정확한 실행 연결, 다른 입력으로의 일반화처럼 구체적인 결과로 입증해야 한다.

  • The Significance of Affectors and Affectees Correlations for Branch Prediction (2008): 데이터 흐름 관계로 유용한 이력을 고르는 가능성을 분석했다. 이상적으로 관계를 아는 조건의 결과와 실제 구현을 구분해야 한다.
  • Whisper (MICRO 2022): 실행 프로파일에서 이력 상관관계를 얻어 수식과 코드 힌트로 활용한다. 컴파일러의 구조 정보가 프로파일만 쓰는 접근에 무엇을 더하는지가 비교 질문이다.
  • By-Software Branch Prediction in Loops (2023): 컴파일러가 분기 계산을 추출해 미리 실행하고 반복 구조로 결과를 연결한다. 관계 정보만 전달하는 접근과 결과를 미리 계산하는 접근은 구분해야 한다.

이 문헌들은 설계의 출발점이다. 이 장의 제안이 새로운 방법이라는 포괄적 주장은 하지 않으며, 직접 비교할 원문과 구현의 차이를 확인해야 한다.

실행 순서와 다음 단계의 조건

순서할 일완료를 확인할 증거
1. 실험 조건 고정코드·바이너리·입력·측정 구간·지표·정보 시점 기록재실행 명령과 버전, 데이터 지원 범위
2. 기준 동작 재현반복 실행, 로그 추가, 개입 없는 재생 검사예측·학습·통계가 원래 동작과 일치
3. 작은 정책 파일럿할당 허용과 값 보정 출력 선택, 단순 비교군 구현갱신 규칙·상태 크기·비용, 평가 전 선택 기준 고정
4. 기회와 한계 분석용량·할당·값 사용의 반응, 값 도착 시점, 관계 선택 측정적용 범위·악화 사례·실행 연결 오류·미지원 항목
5. 고정 평가학습에 쓰지 않은 입력과 동일 비용 대안 비교전체 결과·최악 사례·총비용을 포함한 방향 선택

바로 할 일은 실험 조건과 데이터 지원 범위를 고정하고 기준 동작을 재현하는 것이다. 값과 관계 분석은 필요한 입력 검증을 통과하면 정책 파일럿과 별도로 진행할 수 있다. 아직 확인하지 않은 일정을 확정 마감으로 제시하지 않는다.

무엇을 성공으로 볼 것인가

  • 정확도: 명령어 천 개당 오예측 수(MPKI), 고친 예측과 새로 망친 예측을 함께 보고한다.
  • 실행 성능: 사이클과 사이클당 완료 명령어 수(IPC)는 지원되는 실행 모델에서 측정한다. MPKI 감소를 IPC 증가로 환산하지 않는다.
  • 비용: 예측기·관계 정보·실행 중 상태, 검색 포트, 학습, 복구, 지연과 에너지를 계상한다. 모르는 비용을 0으로 채우지 않는다.
  • 일반화: 같은 입력의 다른 구간과 같은 프로그램의 다른 입력을 구분한다. 정책과 문턱은 최종 평가 전에 고정한다.
  • 재현: 평균뿐 아니라 프로그램별 분포와 최악 사례, 표본 수, 미지원 조건을 남긴다.
다음 단계로 진행할 근거

작은 분석에서 기회가 보이면 구현을 구체화한다. 같은 비용의 단순 대안보다 나은 결과와 총비용을 확인해야 실용 정책을 지지할 수 있다. 한 행동만 유효하면 범위를 줄이고, 지연·복구 비용으로 이득이 사라지면 해당 방향을 보류하거나 중단한다. 최소 이득과 악화 허용 범위는 평가 전에 확정할 항목이다.

반대 경로 준비와 결과 재사용의 결합, 실행 중 경로 수정 제어기, 대형 그래프 신경망은 현재 우선 구현 범위에 포함하지 않는다. 입력·기회·선행연구·비용의 근거를 확보한 뒤 재검토한다.

용어가 낯설다면 12장 용어집과 참고문헌으로 이동하자.
