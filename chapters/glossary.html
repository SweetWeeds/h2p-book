용어집, 종합 퀴즈, 참고문헌

논문을 읽다 막히는 곳은 대개 용어다. 이 장에는 책 전체에 나온 용어를 모아 두었다. 끝까지 읽었다면 종합 퀴즈로 점검하고, 더 깊이 알고 싶은 논문은 원문으로 가자.

용어집

조건부 분기 conditional branch
조건이 참이면 다른 주소로 건너뛰고 거짓이면 다음 명령으로 가는 명령. 이 책에서 "분기"는 대부분 조건부 분기를 뜻한다. 1장
taken, not-taken T, N
분기가 건너뛰면 taken, 그대로 다음 명령으로 가면 not-taken이다. 이 책의 그림에서 청록은 taken, 호박색은 not-taken이다. 1장
정적 분기, 동적 분기 static branch, dynamic branch
정적 분기는 코드 속의 한 위치다. 동적 분기는 그 위치를 실제로 실행한 한 번이다. 같은 정적 분기가 실행마다 다른 결과를 낼 수 있다. 3장
PC program counter
명령의 주소. 예측기는 분기의 PC로 "어느 분기인지"를 구별한다. 2장
fetch
다음에 실행할 명령을 메모리에서 가져오는 단계. 매 cycle 다음 주소가 필요하므로 분기의 방향을 여기서 예측한다. 1장
frontend
명령을 가져오고(fetch) 해석해(decode) 실행부에 공급하는 파이프라인 앞부분. 8장
execute, resolve
execute는 명령을 실제로 계산하는 단계다. 분기가 execute되어 실제 방향이 드러나는 것을 resolve라고 한다. 1장
오예측 misprediction
예측한 방향과 실제 방향이 다른 것. resolve 시점에야 알 수 있다. 1장
squash, flush
오예측이 드러났을 때 잘못된 경로에서 가져온 명령을 모두 취소하는 일. 1장
refill
flush 뒤 올바른 경로의 명령으로 파이프라인을 다시 채우는 과정. 그동안 뒤쪽 단계는 비어 있다. 8장
잘못된 경로 wrong path
오예측한 분기 뒤에 가져와 실행하던 명령들. 결과는 버려지지만 cache와 예측기 상태에는 흔적을 남길 수 있다. 8장
비순차 실행 out-of-order execution, OoO
명령을 프로그램 순서가 아니라 준비된 순서대로 실행하는 방식. "8-wide"는 한 cycle에 최대 8개 명령을 처리하는 코어를 뜻한다.
ROB reorder buffer
실행 중인 명령을 프로그램 순서대로 보관하는 buffer. 크기가 클수록 한 번의 오예측으로 버려지는 명령도 많아질 수 있다.
micro-op μop
프로세서 내부에서 명령을 쪼갠 작은 연산 단위. dependence chain의 길이나 buffer의 용량을 이 단위로 센다.
포화 카운터 saturating counter
taken이면 올리고 not-taken이면 내리되 양 끝에서 멈추는 작은 카운터. 2-bit가 기본이다. 1장
bimodal
분기의 PC로 카운터 표를 찾는 가장 단순한 예측기. history를 쓰지 않는다. 2장
history branch history
앞서 실행한 분기들의 방향이나 경로 기록. 전역(global) history는 모든 분기의 기록을, 지역(local) history는 한 분기의 기록을 가리킨다. 2장
gshare
전역 history와 PC를 XOR해서 카운터 표를 찾는 예측기. history 길이가 하나로 고정된다. 2장
TAGE TAgged GEometric history length
서로 다른 history 길이를 쓰는 여러 tag 표를 두고, tag가 맞는 표 가운데 가장 긴 history의 것을 쓰는 예측기. 지금의 표준이다. 2장
tag
표의 entry가 지금 찾는 분기와 history의 것이 맞는지 확인하는 짧은 식별값. 서로 다른 패턴이 같은 자리를 쓰는 충돌을 걸러 낸다. 2장
provider
TAGE에서 이번 예측을 실제로 내놓은 표의 entry. tag가 맞은 것 중 history가 가장 긴 것이다. 2장
할당 allocation
오예측했을 때 더 긴 history의 표에 새 entry를 만드는 일. 새 entry는 기존 entry를 밀어낸다. 6장
useful 카운터 usefulness counter
entry가 실제로 예측에 도움이 되었는지를 기록하는 값. 0이어야 다른 패턴에게 자리를 내줄 수 있다. 2장
TAGE-SC-L
TAGE에 statistical corrector(SC)와 loop predictor(L)를 더한 예측기. 64KB 구성이 이 책의 논문 대부분이 쓰는 baseline이다. 2장
statistical corrector SC
여러 단서에서 얻은 점수를 더해 TAGE의 예측을 뒤집을지 정하는 보정 구조. RUNLTS는 여기에 register 값의 점수를 더한다. 5장
aliasing
서로 다른 분기나 패턴이 표의 같은 자리를 쓰게 되어 서로의 학습을 방해하는 현상. 2장
confidence
예측기가 자기 예측을 얼마나 믿는지 나타내는 값. 카운터가 포화 상태에 가까울수록 높다. 틀릴 것 같은 분기를 고르는 데 쓴다. 8장
overriding 예측기 overriding predictor
작고 빠른 예측기가 먼저 답하고, 크고 느린 예측기가 몇 cycle 뒤에 그 답을 고치는 구성. 고칠 때마다 가져온 명령 일부를 버린다. 9장
perceptron 예측기
history의 각 bit에 가중치를 두고 그 합의 부호로 방향을 정하는 예측기. 가중치 합 방식은 SC와 BranchNet의 바탕이 된다. 4장
H2P hard-to-predict branch
현재 예측기로 잘 맞히기 어려운 분기. 특정 예측기, 입력, 자원 조건에서의 판단이며 분기의 영구적인 속성이 아니다. 3장
H2P table
분기 PC별로 오예측 횟수를 세어 어려운 분기를 골라내는 작은 표. 논문마다 크기와 판정 기준이 다르다. 3장
coverage, wastage
coverage는 실제 오예측 가운데 미리 어렵다고 표시해 둔 분기에서 난 비율이다. wastage는 어렵다고 표시했지만 실제로는 맞힌 실행의 비율이다. 3장
값 의존 분기 data-dependent branch
방향이 방금 읽은 메모리 값이나 register 값에 달린 분기. 과거 방향만으로는 맞히기 어렵다. 5장
delinquent branch, delinquent loop
오예측을 유난히 많이 내는 분기와, 그런 분기를 품은 루프. Phelps가 쓰는 표현이다. 7장
상관 correlation
어떤 과거 정보(다른 분기의 방향, 값)가 이 분기의 방향을 알려 주는 관계. 예측기가 배우는 대상이다. 4장
noise
관심 분기와 무관한 분기들이 history에 끼어들어 패턴을 흐리는 것. 전체 history를 그대로 외우는 예측기를 어렵게 한다. 4장
CNN, convolution, sum-pooling
CNN은 여러 위치에 나타나는 공통 특징을 학습하는 신경망이다. convolution은 작은 filter를 history 위로 밀며 특징을 찾고, sum-pooling은 구간 안의 반응을 더해 위치 차이를 없앤다. 4장
offline 학습 offline training
프로그램을 미리 여러 입력으로 실행해 모은 기록으로 모델이나 규칙을 만드는 것. 실행 중 학습(online)보다 복잡한 방법을 쓸 수 있지만, 배운 관계가 새 입력에서도 유지되어야 한다. 4장
dependence chain
분기 결과를 만드는 데 필요한 명령들만 거슬러 올라가 이은 연결. backward slice라고도 한다. 5장
선행 실행, 선행 계산 pre-execution, precomputation
main 실행보다 앞서 분기에 필요한 계산만 먼저 수행해 결과를 얻는 것. 예측이 아니라 계산이다. 5장
helper thread
선행 계산을 수행하는 보조 실행 흐름. 별도 엔진에서 돌 수도 있고 같은 코어의 자원을 main과 나눠 쓸 수도 있다. 5장
prediction queue
helper가 계산한 분기 결과를 main이 꺼내 쓸 때까지 보관하는 queue. 같은 분기의 몇 번째 실행인지가 맞아야 한다. 5장
timeliness
결과가 쓸모 있는 시점 안에 도착하는 성질. 정확한 결과도 늦으면 쓸 수 없다. 5장
조기 flush early misprediction flush
선행 계산 결과가 예측과 다를 때, 분기가 실제로 실행되기를 기다리지 않고 바로 flush하는 것. TEA의 핵심이다. 5장
digest
64-bit 값을 몇 bit로 줄인 요약. RUNLTS는 register 값의 digest로 표를 찾는다. 값의 "모양"은 남지만 정확한 크기는 잃는다. 5장
predication, predicate
분기로 건너뛰는 대신 조건값(predicate)으로 명령의 효과를 켜고 끄는 방식. Phelps는 helper 안에서 어려운 분기를 predicate로 바꾼다. 7장
조건부 store guarded store
어떤 분기가 특정 방향일 때만 실행되는 store. 이 store가 뒤의 분기에 영향을 주면 helper도 그 조건을 지켜야 한다. 7장
lock-step
여러 queue가 루프의 반복 번호에 맞춰 함께 나아가는 것. 실행되지 않은 분기의 자리도 건너뛰어 정렬을 지킨다. 7장
용량 capacity
예측기가 담을 수 있는 패턴의 수. 서버 프로그램은 코드가 커서 필요한 패턴이 64KB 예측기의 용량을 넘는다. 6장
profile
프로그램을 미리 실행하며 모은 분기 기록. Whisper와 PURE는 이것을 분석해 실행 중 예측을 돕는다. 6장
hint
offline에서 찾은 예측 규칙을 실행 코드에 실어 보내는 추가 명령. 하드웨어가 실행 중에 읽어 평가한다. 6장
Boolean 식 Boolean formula
입력 bit에 AND, OR 같은 논리 연산을 적용한 규칙. Whisper는 history의 hash에 이 식을 적용해 방향을 정한다. 6장
문맥 context
지금 프로그램이 어디를 실행 중인지 나타내는 요약. LLBP는 최근 무조건 분기들의 주소로 문맥을 정하고, 문맥별로 패턴을 묶어 보관한다. 6장
pattern set, Pattern Buffer
pattern set은 한 문맥에 속한 패턴 묶음이다. Pattern Buffer는 곧 쓸 묶음 몇 개만 올려 두는 작은 구조로, 매 cycle 읽는다. 6장
prefetch
필요해지기 전에 미리 가져오는 것. LLBP는 다음 문맥의 pattern set을 큰 저장소에서 Pattern Buffer로 미리 옮긴다. 6장
문맥 깊이 context depth, W
문맥을 정할 때 돌아보는 무조건 분기의 수. 얕으면 패턴이 한 묶음에 몰리고, 깊으면 같은 패턴이 여러 문맥에 중복된다. 6장
오염 pollution
나중에 쓰이지 않을 패턴이 표의 자리를 차지해 유용한 패턴을 밀어내는 현상. 6장
반대 경로 alternate path
예측하지 않은 쪽의 경로. 예측이 틀리면 이쪽이 올바른 경로가 된다. 8장
Alternate Path Buffer
미리 가져와 해석해 둔 반대 경로의 micro-op을 보관하는 buffer. 오예측이면 여기서 바로 공급한다. 8장
제어 독립 control independence
어떤 명령이 앞선 분기의 방향과 상관없이 실행되는 성질. 이런 명령의 결과는 앞선 분기가 틀렸어도 다시 쓸 여지가 있다. 8장
instance
같은 정적 분기의 여러 실행 가운데 특정한 한 번. 결과를 재사용하거나 queue에서 꺼낼 때는 instance가 맞아야 한다. 8장
signature
여러 정보를 짧게 압축한 식별값. SBRB는 루프 반복 위치를 signature로 만들어 같은 instance를 찾는다. 8장
예측 지연 prediction latency
예측기가 답을 내는 데 걸리는 cycle 수. 표가 크고 계산이 복잡할수록 길어진다. 9장
bubble
파이프라인에서 일하지 않고 지나가는 빈칸. 늦게 나온 정확한 예측이 빠른 예측을 고칠 때 생긴다. 9장
ahead prediction
지금보다 몇 분기 앞의 예측을 미리 계산하기 시작하는 방식. 시작할 때는 그 사이 분기들의 결과를 모른다. 9장
missing history
ahead prediction에서 조회를 시작한 시점과 예측이 쓰이는 시점 사이에 있는, 아직 모르는 분기들의 결과. 9장
secondary tag
미리 읽어 둔 후보와 나중에 드러난 missing history를 잇는 두 번째 tag. 맞는 후보 하나를 고르는 데 쓴다. 9장
MPKI mispredictions per kilo instructions
명령 1,000개당 오예측 수. 낮을수록 좋다. 1장
IPC, speedup
IPC는 cycle당 완료한 명령 수다. speedup은 기준 대비 실행 속도가 얼마나 빨라졌는지다. MPKI 감소율과 같은 값이 아니다. 1장
baseline
비교의 기준이 되는 구성. baseline이 다르면 개선 폭을 직접 비교할 수 없다. 1장
workload
평가에 쓰는 프로그램과 입력. 분기가 어려운 이유가 workload마다 달라 결과가 크게 달라진다. 1장
SPEC CPU, GAP
SPEC CPU는 컴파일러, 탐색, 압축 등 전통적인 벤치마크 모음이다. GAP는 그래프 처리 알고리즘 모음이다. 둘 다 소수의 분기가 오예측 대부분을 만든다. 3장
서버 workload server, data center workload
웹 서버, 데이터베이스, 메시지 큐 같은 응용. 코드가 매우 커서 오예측이 수천 개 분기에 퍼져 있다. 6장
CBP Championship Branch Prediction
정해진 저장 예산과 trace로 예측기의 정확도를 겨루는 대회. 2025년 대회의 예산은 192KB였다. 5장
trace
프로그램 실행에서 뽑은 분기 기록. trace로 하는 평가는 정확도를 재지만 실행 시간(IPC)은 직접 재지 못한다. 5장
SimPoint
긴 프로그램에서 전체를 대표하는 짧은 구간을 골라 그 구간만 시뮬레이션하는 방법. 논문의 "top SimPoint"는 그중 비중이 가장 큰 구간이다.
기하평균 geomean
여러 workload의 speedup을 곱해 거듭제곱근을 취한 평균. 한두 개의 큰 값에 덜 끌려간다.

참고문헌

이 책이 다룬 열두 편이다. "근거 범위"는 이 책이 무엇을 읽고 썼는지를 밝힌다. 공개 초록만 확인한 논문은 초록에 있는 내용만 다뤘다.

    바탕이 된 예측기

    • S. McFarling, "Combining Branch Predictors," DEC WRL Technical Note TN-36, 1993. gshare를 제안했다.
    • A. Seznec and P. Michaud, "A case for (partially) TAgged GEometric history length branch prediction," Journal of Instruction-Level Parallelism, 2006. TAGE를 제안했다.
    • A. Seznec, "TAGE-SC-L Branch Predictors Again," 5th Championship Branch Prediction, 2016. 이 책의 논문 대부분이 baseline으로 쓰는 64KB TAGE-SC-L이다.
    이 책의 그림과 실험에 대하여

    구조도는 원문을 참고해 모두 새로 그렸다. 실험은 원리를 보여 주는 축소 모델이며 논문의 측정 결과를 재현한 것이 아니다. 논문이 보고한 수치는 본문에서 조건과 함께 따로 표시했다.
